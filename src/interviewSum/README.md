# Interview Script Analysis Tool - 使用指南

## 功能概述

这是一个基于 OpenRouter API 和 GPT-4-mini 的面试脚本分析工具，可以自动分析面试记录并生成结构化的分析结果。

### 核心功能

1. **亮点提取** - 识别求职者的优秀表现点
2. **不足识别** - 指出需要改进的方面
3. **关键词提取** - 提取关键的技术词汇、公司名、项目名等
4. **时间线总结** - 按时间顺序组织面试内容

## 输入格式

### 推荐格式

```
00:00:10 - 面试官: 你好，欢迎来面试
00:00:30 - 求职者: 感谢邀请，很高兴见到你
00:01:00 - 面试官: 请自我介绍一下
00:02:10 - 求职者: 我叫张三，有5年的React和Node.js开发经验，主要做过电商平台和内容管理系统
00:04:00 - 面试官: 在你的项目中，如何处理性能优化的？
00:05:30 - 求职者: 我使用了code splitting、lazy loading、虚拟化列表等技术，将首屏加载时间从3秒优化到1秒
00:08:00 - 面试官: 有没有遇到什么技术难点？
00:09:15 - 求职者: 有的，React的Context API在大项目中会导致性能问题，我通过使用Redux和字节跳动的Zustand解决了这个问题
00:12:00 - 面试官: 你的技术栈是什么？
00:13:30 - 求职者: React、Vue、Node.js、Express、MongoDB、PostgreSQL、Docker、Kubernetes，还有一些AWS经验
00:16:00 - 面试官: 有没有什么问题想问我的？
00:17:00 - 求职者: 我很感兴趣贵公司的技术方向和团队规模
```

### 简化格式

```
00:00 面试官: 你好
00:30 求职者: 你好，谢谢
01:00 面试官: 请自我介绍
02:10 求职者: 我有5年开发经验
```

### 格式要求

- 时间戳格式：`HH:MM:SS` 或 `MM:SS` 或 `HH:MM`
- 说话人标识：`面试官:`、`求职者:` 或其他标签
- 内容部分：说话人后的任何文本

## 输出格式

### 亮点 (Highlights)
展示求职者表现优秀的方面
- 技术能力强
- 经验丰富（如"5年React开发经验"）
- 解决问题能力强
- 思维清晰

### 不足 (Lowlights)
需要改进的方面
- 技术栈不完整
- 缺乏某些经验
- 表达不清楚
- 对某些问题的理解不足

### 关键词实体 (Entities)
从对话中提取的关键词
- 技术栈：React、Vue、Node.js、Express、MongoDB、PostgreSQL、Docker、Kubernetes、AWS
- 公司/项目名
- 具体的技术方案

### 时间线总结 (Timeline Summary)

| 时间戳 | 环节标题 | 内容总结 |
|--------|---------|---------|
| 00:00:10 | 开场介绍 | 面试官欢迎求职者 |
| 00:02:10 | 自我介绍 | 求职者介绍了个人背景和5年开发经验 |
| 00:05:30 | 技术讨论 | 讨论了性能优化技术，包括code splitting和lazy loading |
| 00:09:15 | 技术难点 | 分享了处理React Context性能问题的方案 |
| 00:12:00 | 技术栈 | 介绍了完整的技术栈包括前后端和云平台 |

## 使用步骤

1. **访问页面**
   ```
   http://localhost:3000/demo/interviewSum
   ```

2. **粘贴面试脚本**
   - 在输入框中粘贴或输入面试脚本
   - 支持上述格式的脚本

3. **点击分析**
   - 点击"🚀 开始分析"按钮
   - 等待进度条完成（通常 2-5 秒）

4. **查看结果**
   - 亮点部分：看到哪些地方表现不错
   - 不足部分：需要改进的方面
   - 关键词标签：提取的技术词汇
   - 时间线：完整的面试流程梗概

## API 配置

使用的 OpenRouter API 配置：

```javascript
OPENROUTER_API_URL: 'https://openrouter.ai/api/v1'
OPENROUTER_API_KEY: 'xxx'
MODEL: 'openai/gpt-4-mini'
```

## 故障排除

### 问题 1: API 报错

**现象**: 显示 "API 错误 (429): Rate limited"

**解决**: API 可能达到了速率限制，请稍等片刻后重试

### 问题 2: JSON 解析失败

**现象**: 显示 "分析结果解析失败"

**解决**: 
- 检查脚本格式是否正确
- 确保有时间戳和说话人标识
- 尝试简化脚本内容

### 问题 3: 结果为空

**现象**: 显示 "暂无相关数据"

**解决**:
- 增加脚本内容的详细程度
- 检查时间戳格式是否正确
- 重新提交分析

## 性能优化建议

- 脚本长度：建议不超过 2000 字符
- 内容详细度：包含更多细节会获得更准确的分析
- 格式规范：规范的格式能提高解析准确率

## 常见问题

**Q: 可以分析中文以外的语言吗？**
A: 可以的，支持英文、日文等多种语言

**Q: 分析结果准确度如何？**
A: 准确度取决于 GPT-4-mini 模型的性能，通常 80-90% 准确

**Q: 可以导出分析结果吗？**
A: 当前可以复制结果，后续版本会支持 PDF 导出

**Q: 脚本是否会被保存？**
A: 不会，所有数据在浏览器本地处理，不会发送到服务器存储
